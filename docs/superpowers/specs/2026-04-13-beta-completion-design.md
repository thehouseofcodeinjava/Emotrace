## 1. SettingsService

**File:** `lib/services/settings_service.dart`

Follows the same pattern as `MoodService`. Single responsibility: read/write the `settings` table.

```
loadSettings(String userId) → Future<Settings?>
  Query: SELECT * FROM settings WHERE user_id = ? LIMIT 1
  Returns null on first launch (no row yet)

saveSettings(Settings settings) → Future<void>
  Insert OR REPLACE into settings table
```

---

## 2. SettingsProvider (updated)

- Add `loadSettings()` — calls `SettingsService.loadSettings()`, falls back to `Settings.defaults()` if null, stores in `_settings`
- Each mutator (`updateTheme`, `toggleReminder`, `updateReminderTime`) calls `SettingsService.saveSettings()` after updating state
- `toggleReminder` also calls `NotificationService.scheduleDailyReminder()` or `cancelDailyReminder()`
- `updateReminderTime` also calls `NotificationService.scheduleDailyReminder()` if reminders are enabled

## 3. NotificationService (full impl)

**File:** `lib/services/notification_service.dart`  
**Package:** `flutter_local_notifications ^17.2.3` (already in pubspec)

```
init()
  - Android: create channel 'emotrace_daily', importance: high
  - iOS/macOS: request alert + badge + sound permissions
  - No-op if permission denied (graceful degradation)

scheduleDailyReminder(String time)   // 'HH:mm'
  - Parse hours/minutes from time string
  - Schedule daily repeating notification at that time (ID: 1)
  - Notification: title 'Time to check in 🌿', body 'How are you feeling today?'

cancelDailyReminder()
  - Cancel notification ID 1
```

Wired in `main.dart`: `await NotificationService().init()` after DB init.

## 4. PDF Export

**Package:** `pdf: ^3.10.8` + `printing: ^5.13.1`  
**New file:** `lib/services/pdf_service.dart`

### 4a. Full History PDF (Settings → Data → Export Data)

Content:
- Header: EMOTRACE logo text + "Mood History Report" + export date
- Summary row: total entries | avg mood | current streak | longest streak
- Table: Date | Score | Emoji | Emotions | Notes — one row per entry (last 90 days, newest first)
- Footer: "Generated by EMOTRACE"

Colours: teal `#06D6A0` headers on dark `#1C1B1B` background. White body text.

### 4b. 30-Day Insights PDF (Insights screen → share icon in AppBar)

Content:
- Header: EMOTRACE + "Monthly Insights Report" + date range
- Hero: Stability score + avg mood (large typography)
- Pattern section: best day / worst day (if available)
- Top emotions: text-based bar representation (name + count + `████░░` bar)
- Footer: entry count + "Generated by EMOTRACE"

### Delivery

Both use `Printing.sharePdf(bytes: pdfBytes, name: 'emotrace_<type>_<date>.pdf')` to trigger the OS share sheet (works on Android + iOS).

`PdfService` exposes two static methods:
- `buildHistoryPdf(List<MoodEntry> entries, int currentStreak, int longestStreak) → Future<Uint8List>`
- `buildInsightsPdf(Insights insights, List<MoodEntry> entries) → Future<Uint8List>`

## 5. AppRoutes Wiring

Add `onGenerateRoute: AppRoutes.generateRoute` to `MaterialApp` in `main.dart`. Define `generateRoute` in `routes.dart` as a static method that maps named routes to screens.  
Navigation in `HomeScreen` and anywhere else already using `MaterialPageRoute` can remain as-is — this just adds named route support without breaking existing nav.

## Error Handling

- Settings load failure → fall back to `Settings.defaults()`, never crash
- Notification permission denied → silent no-op (no crash, reminder toggle shows as off)
- PDF generation failure → show SnackBar error, never crash
- DB save failure → log error, state still updates in memory (UX not blocked)
